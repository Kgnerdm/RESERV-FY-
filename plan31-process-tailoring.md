# PLAN31 – Process Tailoring Using Organizational Assets

This document describes how the Reservify team adapted standard processes and templates to fit the unique needs of the project, in alignment with organizational assets and academic guidelines.

---

## 1. Tailored Processes

| Standard Asset        | Customization Description                                | Rationale                                                       |
|------------------------|----------------------------------------------------------|------------------------------------------------------------------|
| Requirement Analysis   | Used Google Forms for collecting mock stakeholder input  | Fast simulation for early requirement gathering                 |
| Git Commit Process     | Added `#IssueNo` reference in all commits                | Ensures traceability between code and project plan              |
| Review Checklist       | Customized peer-review table for each plan document      | Matches academic group work format and feedback tracking        |
| Task Tracking          | Used GitHub Issues instead of Jira/MS Project            | Lightweight, accessible to all team members                    |
| Documentation Format   | Markdown `.md` used with GitHub rendering                | Easily editable and versioned alongside codebase               |

---

## 2. Roles and Tools Assigned

- **Project Manager (Kağan Erdem):** Oversaw adaptation of assets and documentation standards
- **Technical Lead (Recep Buğra Sarıkaya):** Tailored API structure and backend conventions to match modular task tracking
- **Integrator (Ahmet Hilmi Büber):** Mapped testing methods to fit minimal QA cycles while maintaining test coverage

---

## 3. Tailoring Goals

- Maintain consistency across GitHub Issues, commits, and plan files
- Ensure every academic deliverable is versioned and traceable
- Avoid over-engineering by customizing only essential assets

---

## Summary

The Reservify project tailored all processes with a minimal-yet-effective approach using GitHub-native workflows and markdown-based documentation. All customizations ensured alignment with both real-world software practices and academic expectations.
